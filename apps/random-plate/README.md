# Random Plate — v0 Stage 1

기획서 [`docs/random-plate/PLAN_v2.md`](../../docs/random-plate/PLAN_v2.md)의 Stage 1 구현.
링크 하나로 팀이 같이 점심 메뉴를 정하는 웹앱의 첫 조각 — **혼자 뽑기 전체 플로우**.

## 지금 되는 것

- 위치 획득 (HTML5 Geolocation → 실패 시 프리셋 6곳)
- 반경 선택 (400 / 800 / 1200m)
- 8칸 룰렛 → 당첨 → 결과 카드 → 카카오맵 링크 / 공유
- 후보 풀 고정 + 리롤 (리롤 시 외부 API 호출 0회)

## 아직 없는 것 (Stage 2)

- 방 생성 / 링크 공유 / 실시간 팀 투표 → Supabase 필요
- 주소·역명 검색 폴백 → 카카오 키워드 검색 API 필요

```bash
npm install
npm run dev      # http://localhost:3000
```

## 설계 메모

**캐싱 (기획서 §3.3)** — 좌표를 소수점 3자리(약 110m) 격자로 스냅해 캐시 키로 쓰고,
방 하나당 후보 풀을 한 번만 조회해 고정한다. 그래서 리롤·재추첨이 아무리 많아도
API 호출이 늘지 않는다. 호출량은 `사용자 수 × 리롤 횟수`가 아니라 `조회 지점 수`에 비례한다.

**위치 정보 (기획서 §9)** — 서버는 정밀 좌표를 받는 즉시 격자로 반올림해 버리고,
이후 모든 처리에 격자 좌표만 쓴다. 정밀 위치는 저장되지 않는다.

**룰렛 정합성** — 12시 포인터 아래로 당첨 섹터를 데려오는 최소 회전량을 계산하고
섹터 폭 안에서만 흔든다. Playwright로 최종 회전각을 읽어 포인터 위 섹터와 결과
카드가 일치하는지 검증했다 (4/4 통과).

**섹터 라벨** — 상호명을 섹터에 새기면 휠이 돌 때 뒤집히고 7자로 잘려 읽히지 않아,
섹터에는 번호만 두고 이름은 휠 아래 목록에서 읽게 했다.
