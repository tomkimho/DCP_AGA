# Random Plate — v0 Stage 1

기획서 [`docs/random-plate/PLAN_v2.md`](../../docs/random-plate/PLAN_v2.md)의 Stage 1 구현.
링크 하나로 팀이 같이 점심 메뉴를 정하는 웹앱의 첫 조각 — **혼자 뽑기 전체 플로우**.

## 지금 되는 것

- **내 위치 지도에서 시작** — 접속 즉시 Geolocation, 지도를 끌어 중심 이동
- 반경 선택 (400 / 800 / 1200m) — 반경 안 후보 수가 지도에 실시간 반영
- 게임 4종: 룰렛 / 슬롯머신 / 러시안 룰렛 / 카드 뽑기
- Web Audio 합성 효과음 + 음소거 토글
- 결과 카드 → 지도 링크 / 공유 / 다시 하기
- 후보 풀 고정 + 리롤 (리롤 시 외부 API 호출 0회)

## 아직 없는 것 (Stage 2)

- 방 생성 / 링크 공유 / 실시간 팀 투표 → Supabase 필요
- 주소·역명 검색 폴백 → 카카오 키워드 검색 API 필요

## 실행

```bash
npm install
npm run dev      # http://localhost:3000
```

## 환경변수

| 변수 | 필수 | 없을 때 동작 |
|---|---|---|
| `KAKAO_REST_API_KEY` | 아니오 | 가상의 데모 식당 데이터로 폴백하고 UI에 "데모 데이터" 배지 표시 |
| `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | 아니오 | 캔버스로 그린 폴백 지도 사용 (타일 없음, 좌표·거리는 정확) |

Vercel에서는 Project Settings → Environment Variables에 등록합니다.

### 구글 지도 키 (`NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`)

Google Cloud Console에서 프로젝트를 만들고 **Maps JavaScript API**를 켠 뒤 키를
발급받습니다. 결제 계정 연결이 필요합니다.

- 이 키는 **브라우저에 그대로 노출**됩니다(`NEXT_PUBLIC_` 접두사가 그 뜻). 반드시
  **HTTP 리퍼러 제한**으로 배포 도메인만 허용하고, **Maps JavaScript API 한 개로
  API 제한**을 걸어야 합니다. 그게 유일한 방어선입니다.
- 키가 거부되면(`gm_authFailure`) 회색 지도로 죽지 않고 캔버스 지도로 되돌아가며
  사유를 화면에 표시합니다.
- 무료 한도와 과금 정책은 자주 바뀝니다. **쓰기 전에 현재 요금표를 직접 확인**하세요.

### 카카오 로컬 키 (`KAKAO_REST_API_KEY`)

식당 데이터용입니다. 서버(`/api/places`)에서만 쓰이며 브라우저로 나가지 않습니다.
**절대 `NEXT_PUBLIC_` 접두사를 붙이지 마세요.**

> ⚠️ 프로덕션 공개 전 확인 필요: 카카오 로컬 API의 일일 쿼터, 상업적 이용 조건,
> `place_url` 딥링크 사용 약관. 기획서 §3.1 / §13-1 참조.

## 설계 메모

**캐싱 (기획서 §3.3)** — 좌표를 소수점 3자리(약 110m) 격자로 스냅해 캐시 키로 쓰고,
방 하나당 후보 풀을 한 번만 조회해 고정한다. 그래서 리롤·재추첨이 아무리 많아도
API 호출이 늘지 않는다. 호출량은 `사용자 수 × 리롤 횟수`가 아니라 `조회 지점 수`에 비례한다.

**위치 정보 (기획서 §9)** — 서버는 정밀 좌표를 받는 즉시 격자로 반올림해 버리고,
이후 모든 처리에 격자 좌표만 쓴다. 정밀 위치는 저장되지 않는다.

**지도** — 구글 지도(Maps JavaScript API)와 캔버스 폴백을 같은 인터페이스
(`components/map/MapView.tsx`)로 감쌌다. 키 유무·키 거부 여부에 따라 자동으로
갈리므로 나머지 코드는 어느 쪽인지 알 필요가 없다.

**데모 장소** — 절대 좌표를 130m 격자로 나눠 칸마다 결정론적으로 가게를 둔다.
중심 기준으로 생성하면 지도를 끌 때 가게가 따라와서 지도처럼 보이지 않는다.
밀도 필터(`h % 3`)와 이름 선택(`h % 45`)은 반드시 서로 다른 해시를 써야 한다 —
45 = 3 × 15이라 같은 해시를 쓰면 45개 이름 중 15개만 뽑힌다.

**룰렛 정합성** — 12시 포인터 아래로 당첨 섹터를 데려오는 최소 회전량을 계산하고
섹터 폭 안에서만 흔든다. Playwright로 최종 회전각을 읽어 포인터 위 섹터와 결과
카드가 일치하는지 검증했다 (4/4 통과).

**섹터 라벨** — 상호명을 섹터에 새기면 휠이 돌 때 뒤집히고 7자로 잘려 읽히지 않아,
섹터에는 번호만 두고 이름은 휠 아래 목록에서 읽게 했다.
